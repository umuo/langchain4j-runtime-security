# 下一版发布说明（草稿，尚未发布）

本页整理 `0.1.0-alpha.1` 之后的接入变化，供下一次 Maven Central 发布使用。当前源码版本仍为 `0.1.0-SNAPSHOT`；发布版本号需在发布前确认，本文不代表新的 Central 制品已经可下载。不要覆盖已有 release。

## 用户需要关注的变化

| 变化 | 使用方式与影响 |
| --- | --- |
| 不传策略路径时跳过 Agent 初始化 | 仅指定 `-javaagent:/path/agent-security-javaagent.jar` 不安装 transformer，不初始化安全线程；适合先挂载再启用。存在的空策略文件仍启用检查。 |
| 文本长度默认不限 | `max.text.chars` 未配置、空值或纯空白时不限制单次提取、拼接后的文本长度。需要上限时显式填写正整数；流式缓冲、工具 JSON 等独立容量限制仍生效。 |
| 配置预检查 | 运行 `java -cp agent-security-javaagent.jar io.agentsecurity.agent.PolicyCheck /path/policy.properties`，先检查策略和关联工具文件，再重启业务；该入口不执行插桩、不调用远程检测、不创建审计文件。 |
| 拒绝重复属性键 | 重复键不再按最后一项覆盖，而是报告配置错误；转义后相同的键也视为重复。上线前删除重复项。 |
| 按 ClassLoader 复用 SPI Detector | 同一应用加载器的不同请求类型共用插件实例，避免模型、工具等路径重复构造。插件必须支持并发；不同应用加载器保持隔离。初始化失败会在该加载器下持续拒绝，修复后重启。 |
| 性能验证工具 | 新增真实打包 Agent 的六模式基准，检查业务结果和实际调用数，输出多 JVM 的延迟、吞吐、首段交付、GC 与审计字节数。模拟业务结果不能代替生产容量评估。 |

版本准入与支持边界见 [兼容性说明](langchain4j-compatibility.md)，插件生命周期和线程安全要求见 [扩展指南](sdk-extension.md)。

## 迁移步骤

1. 在测试环境构建最新源码，使用同一构建的 SDK、Agent 和业务插件。
2. 对生产策略执行 `PolicyCheck`；检查重复属性、空值和相对路径。
3. 若希望维持旧版本的默认文本上限，显式添加 `max.text.chars=100000`。
4. 检查自定义 Detector：构造函数不依赖某一种请求类型；可变状态支持并发；动态策略通过版本化扩展更新，不能依赖重复构造刷新配置。
5. 用实际项目验证允许、拒绝、检测异常、并发及流式行为，再决定上线。文件审计强制刷盘的开销应单独评估。

## 发布步骤

先完成仓库发布验收与 Wiki 严格构建，再按 [Central 发布手册](maven-central-publishing.md) 选择未使用的版本、执行签名上传、检查 Portal 验证结果。只有实际发布完成且可以下载后，才更新手册中的推荐 Maven 版本和本页状态。上传和正式发布尚未在本轮执行。
