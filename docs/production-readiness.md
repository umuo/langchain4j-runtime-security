## 范围与边界

保护正常应用内的 Agent 调用，不承诺抵御已可在 JVM 任意执行代码的攻击者。业务 SQL / 文件 / 网络权限仍由资源端执行，SDK 不能替代资源鉴权或操作系统沙箱。提示注入分类不能提供绝对正确保证，必须报告误报／漏报并配合确定性工具策略。

已修复回调流未检查即输出的原型缺口，并接入模型 Flow 流、结构化工具权限、可信上下文、RAG 与 Memory 边界；目前流式使用完整缓冲后释放，首字延迟随完整生成时间增加。下一阶段补 MCP 独立边界、远程检测及运行指标，并继续发布与性能验收；不能把未支持路径简单写成“全覆盖”。

## 同 JVM 多 Agent 委托

新增显式 AgentRuntime，提供受限父子执行登记、工具／检索器／Memory 资源范围、身份校验、单次执行、异步提交、过期与子树撤销。固定委托检查接入 PolicyEngine，生命周期和决策审计使用 schema 3。业务认证、根任务授权、具体任务代码绑定仍由可信宿主负责；当前不支持跨服务凭据、自动推断任意框架父子调用、恶意 JVM 代码隔离或原子撤销外部副作用。接入与迁移见 [多 Agent 安全](multi-agent-security.md)。
