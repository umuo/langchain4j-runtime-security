## 范围与边界

保护正常应用内的 Agent 调用，不承诺抵御已可在 JVM 任意执行代码的攻击者。业务 SQL / 文件 / 网络权限仍由资源端执行，SDK 不能替代资源鉴权或操作系统沙箱。提示注入分类不能提供绝对正确保证，必须报告误报／漏报并配合确定性工具策略。

已修复回调流未检查即输出的原型缺口，并接入模型 Flow 流、结构化工具权限、可信上下文、RAG 与 Memory 边界；目前流式使用完整缓冲后释放，首字延迟随完整生成时间增加。已补远程检测客户端与运行指标；已补 MCP 工具独立边界，已补资源/提示词与本机传输实测，下一阶段补发现接口与响应容量限制，并继续发布与性能验收；不能把未支持路径简单写成“全覆盖”。

## 多 Agent 共享预算与取消迭代

新增每根任务的累计登记数、入口检查数预算，后代共享且完成不退款；并发扣减与登记、失效共用 runtime 锁，超额会终止整棵树。新增 `cancel()`，取消先完成时 `call`／`submit` 不再交付成功结果；并补入过期清理后登记子任务前的父委托复检。经 PolicyEngine 拒绝的预算异常归入结构化容量诊断。详细用法和计数语义见 [共享预算与协作式取消](multi-agent-budget.md)。

这是同 JVM 的权限与结果治理，不强制停止业务线程或外部 I/O，不回滚副作用。排队 future 等执行器处理后才会异常完成；登记释放不代表实际工作已经停止。token／金额、跨服务一致预算、外部任务物理取消和长期压力仍未验收。
